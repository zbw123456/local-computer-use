# 权限与排错

| 现象 | 处理方式 |
|---|---|
| `swift` 不存在 | 安装 Apple Xcode Command Line Tools，再重开终端 |
| `python3` 不存在或版本太旧 | 安装 Python 3.10+；演示不需要额外 Python 包 |
| 原生组件尚未编译 | 在项目目录执行 `./scripts/build-native.sh` |
| 辅助功能未授权 | 在系统设置中为实际启动程序或 helper 开启辅助功能；退出再重开 |
| 截图未授权、窗口标题为空 | 开启屏幕录制权限；系统可能要求重新打开启动程序 |
| 已授权仍显示未连接 | 确认授权的是这次运行的终端 / IDE / helper，路径没有改变；重启它们再检查 |
| 窗口列表为空 | 打开一个未最小化的普通应用窗口；此版本仅列出可见窗口 |
| 无法匹配辅助功能窗口 | 该应用可能未提供标准 AX 窗口，或窗口在读取时移动；尝试普通编辑应用 |
| 界面控件太少 | 应用可能使用自绘界面；尝试可验证命中位置的坐标动作，无法验证时程序会停止 |
| 窗口或控件已变化 | 停止本轮任务，刷新窗口和截图后重新开始 |
| 坐标被拒绝 | 坐标需要对应截图像素；窗口被其他窗口覆盖、移动或出现新弹窗时也会被拒绝 |
| `set_value` 不支持 | 模型可改用当前文本框的 `type_text`；需要新一轮观察和批准 |
| HTTP 401 / 403 | 检查 API Key、模型访问权限及端点，不要贴出密钥排错 |
| HTTP 429 | 检查模型额度和请求限制；程序不会不断自动重试 |
| 本地模型报参数不支持 | 需要完整 Responses API 兼容能力；只有 Chat Completions 的服务不能直接接入 |
| 连接口令无效 | 服务重启后旧页面口令失效，使用终端新显示的完整链接 |
| 端口已占用 | 使用 `python3 -m localcu --port 8766` |
| 本机服务无法启动，提示不允许操作 | IDE 或代理运行环境可能禁止监听端口；在自己的终端运行 |
| 点击停止后仍显示忙碌 | 等待当前模型请求或原生调用退出；停止不会撤回已经发出的动作 |

## 在受限构建环境中

脚本将 Swift 和 Clang 缓存放在项目 `.local/`，避免写入不可用的用户缓存路径。如果运行环境不支持 SwiftPM 自身的嵌套沙箱，可以在信任项目源代码的前提下传入：

```sh
./scripts/build-native.sh --disable-sandbox
```

这个选项只影响 SwiftPM 构建过程，不会赋予辅助功能或屏幕录制权限，也不会关闭 macOS 系统安全机制。普通终端通常不需要此选项。

## 提交问题时

提供系统版本、Python / Swift 版本、错误文字、演示是否正常，以及出问题的动作类型即可。需要提供截图时先确认没有个人信息。不要提交 `.env`、真实窗口观察、API Key 或完整私人任务内容。
